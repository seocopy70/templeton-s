# Phase 4 — 뉴스·공시 이벤트 설계 v0.1

> 템플턴S 마스터 문서 §8, §11-E/F, Phase 4 기준  
> 작성: 2026-08-27

## 1. 목표

가격·재무만으로 계산한 Score에 **이벤트 맥락**을 더한다.

```
실시간 가격 변화 감지
        ↓
  중요한 변화인가?
   ├── 아니오 → Score만 갱신 (현재와 동일)
   └── 예     → 뉴스/공시 확인 → AI 재분석 → 의견 갱신
```

AI에게 숫자만 넘기지 않고,  
**“왜 움직였는지”** 후보 사건을 함께 넘긴다.

## 2. 원칙 (마스터 문서와 동일)

| 층 | 역할 | 예시 |
|----|------|------|
| FACT | API·수집기가 수집 | 공시 제목, 뉴스 헤드라인, 시각 |
| ANALYSIS | 프로그램이 분류 | 중요도, 호재/악재, 가치 영향 여부 |
| AI | 해석 | “개별 악재 vs 시장 공포” 문장 |
| DECISION | 의견·변경조건 | Score 보정 또는 의견 유지 |

- 프로그램이 계산·분류하고, AI는 해석만 한다.
- 확신이 부족하면 **판단 보류**를 허용한다.
- 자동매매는 하지 않는다.

## 3. 이벤트 유형

### 3.1 공시 (한국 DART 우선)

| 유형 | 예시 | 기본 중요도 |
|------|------|-------------|
| 실적 | 잠정실적, 실적발표 | high |
| 자본 | 유상증자, 전환사채 | high |
| 자사주 | 취득/처분 신탁 | medium |
| 배당 | 현금배당 결정 | medium |
| 계약 | 단일판매·공급계약 | medium~high |
| 지배구조 | 대표이사 변경, 최대주주 | medium |
| 리스크 | 소송, 횡령, 회계 | critical |
| 기타 | 단순 공시 | low |

### 3.2 뉴스

| 분류 | 의미 |
|------|------|
| 호재 | 가치에 긍정적 영향 가능 |
| 악재 | 가치에 부정적 영향 가능 |
| 중립 | 노이즈·반복 보도 |
| 치명적 악재 | 존립·회계·규제 리스크 |

템플턴 관점 추가 질문:
> 이 뉴스가 **기업의 내재가치를 바꾸는가**,  
> 아니면 **시장 심리만 흔드는가**?

## 4. 데이터 소스 (1차)

| 우선순위 | 소스 | 용도 | 비고 |
|----------|------|------|------|
| 1 | **DART Open API** | 한국 종목 공시 | 공식, 구조화에 유리 |
| 2 | KIS/시세 연계 없음 | — | 공시는 DART 분리 |
| 3 | 네이버·증권 RSS/검색 (선택) | 뉴스 헤드라인 | 1차에는 선택, 품질 검증 후 확대 |
| 4 | SEC EDGAR (이후) | 미국 관련 ETF·ADR | Phase 4.2 |

MVP(6종목) 기준:
- 개별주(삼성전자, 현대차, KB금융) → DART 공시 필수
- ETF 3종 → 발행사 공시·지수 뉴스 우선, 개별 공시 비중 낮음

## 5. 이벤트 스키마 (초안)

```json
{
  "event_id": "dart-20260827-001",
  "source": "dart",
  "symbol": "005930",
  "name": "삼성전자",
  "ts": "2026-08-27T09:15:00+09:00",
  "title": "연결재무제표기준영업(잠정)실적",
  "category": "earnings",
  "importance": "high",
  "sentiment": "neutral",
  "value_impact": "possible",
  "url": "https://...",
  "raw_summary": "..."
}
```

| 필드 | 설명 |
|------|------|
| importance | low / medium / high / critical |
| sentiment | positive / negative / neutral / critical_negative |
| value_impact | unlikely / possible / likely — **내재가치 영향 추정(규칙 기반 1차)** |

## 6. Score·의견과의 연결

Phase 4에서는 Score 공식을 당장 크게 바꾸지 않는다.

1. **이벤트 없음** → 기존 v0.5 Score 유지  
2. **medium 이상 이벤트** → AI 해석 입력에 이벤트 목록 추가  
3. **critical** → 의견에 “공시 확인 필요” 플래그, 판단 변경 조건 자동 추가  
4. (이후) 이벤트 기반 **소폭 가점/감점**은 백테스트 후 Phase 5~7에서 결정

## 7. 트리거 조건 (가격 이벤트)

마스터 문서 §8 예시 구체화:

| 조건 | 동작 |
|------|------|
| 당일 등락 \|Δ\| < 1.5% 및 시장 대비 상대 하락 < 1.5%p | Score만 갱신 |
| \|Δ\| ≥ 3% 또는 상대 하락 ≥ 2%p | 공시/뉴스 조회 후 AI 재분석 |
| critical 공시 수신 | 가격 무관 즉시 재분석 |

초기에는 **폴링(수 분~수십 분)** 으로 충분. WebSocket 실시간 공시는 이후.

## 8. 모듈 구조

```
src/
  events/
    __init__.py
    schema.py          # Event dataclass / dict 스키마
    dart_client.py     # DART 공시 조회
    news_client.py     # (선택) 뉴스 헤드라인
    classifier.py      # 규칙 기반 중요도·sentiment
    trigger.py         # 가격 변화 → 재분석 여부
  decision_log.py      # 이벤트 id를 extra에 기록 가능
```

AI 레이어(`ai_interpreter`) 확장:
- `generate_comment(..., events: list[dict] | None = None)`
- 프롬프트에 이벤트 3~5개 요약 삽입

## 9. 구현 단계

| Step | 내용 | 성공 기준 |
|------|------|-----------|
| **4.0** | 스키마 + 빈 모듈 + 설계 문서 | import 가능 |
| **4.1** | DART 공시 1종목 조회 | 삼성전자 최근 공시 N건 출력 |
| **4.2** | 규칙 기반 classifier | 제목 키워드 → importance |
| **4.3** | 대시보드에 “최근 공시” 섹션 | 종목 카드 또는 하단 표시 |
| **4.4** | 가격 트리거 + AI 프롬프트 연결 | 급락 시 공시 포함 코멘트 |
| **4.5** | 판단 기록에 event_ids 저장 | decisions.jsonl 검증 |
